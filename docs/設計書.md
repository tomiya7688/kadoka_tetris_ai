# 簡単な設計書

## 目的
対戦テトリスを作り、人間対CPUとAI同士の対戦を共通の仕組みで実行する。
両陣営は外部からのコマンド入力で操作可能とする。

## 構成
~~~mermaid
flowchart LR
    Human[キーボード] --> Command[コマンド受付]
    External[外部プログラム] --> Command
    AI[プレイAI] --> Command
    Command --> Match[進行・対戦調整]
    Match --> Core[ゲームコア]
    Core --> Observation[公開観測]
    Observation --> AI
    Observation --> View[Pygame表示]
~~~

コアは描画なしで動作し、AIのシミュレーションにも利用する。
描画用状態とAI用観測は区別し、観測には公開情報だけを含める。

## 初期ルール案
以下は本プロジェクトの初期案。実装時に詳細仕様とテストで固定する。
公式仕様への完全準拠は現時点では目標に含めない。

| 項目 | 初期案 |
| --- | --- |
| 盤面 | 幅10、可視20行、上部の非表示2行 |
| 座標 | 左上原点、xは右、yは下へ増加。内部y=0,1は非表示 |
| ミノ | I、O、T、S、Z、J、L |
| ツモ | 7種を1回ずつ含む7-bag。専用のseed付き乱数を使用 |
| NEXT | 公開する次の5個 |
| HOLD | 1回の固定まで1回。交換時は出現位置・向きに戻す |
| 進行 | 固定tick。重力とロック待ちはtick単位の設定 |
| 回転 | 回転状態と壁蹴り表を詳細仕様で定義してから実装 |
| 敗北 | 出現不能と上部固定の条件を詳細仕様で固定 |
| 対戦 | おじゃま行、攻撃量、相殺、同時攻撃順を段階導入 |

## コマンドと状態遷移
意味的操作は move_left、move_right、rotate_cw、rotate_ccw、
soft_drop、hard_drop、hold を想定する。
一時停止や再開始は対戦セッション用の別コマンドとする。

入力には対象プレイヤー、実行tick、連番、操作名を持たせる。
受付側で形式、対象、操作名、過去tick、重複連番を検証する。
同一tickの順序、入力数の上限、操作不能時の扱いはコマンド実装時に確定する。
キーリピートは入力アダプターでコマンド化し、コアからキー状態を参照しない。
外部接続はまずローカルのJSON Lines入出力を想定する。

処理順は入力適用、重力・固定、ライン消去、攻撃算出、
両者の攻撃相殺・おじゃま処理、次の出現・敗北判定を基本案とする。
対戦の両者は同じtickで更新し、一方を先に処理したことで有利にならない設計にする。
詳細な例外と順序は対戦実装前に仕様化する。

## プレイAI
AIは盤面、操作中ミノ、HOLD、公開NEXT、おじゃま予告などを観測する。
未公開ツモ、乱数状態、相手AI内部状態にはアクセスしない。

最初は到達可能な置き場所と操作列を探索し、評価関数で選ぶ。
瞬間移動による配置を本番へ直接適用せず、選んだ操作列を共通コマンドへ変換する。
盤面が変化して操作列が無効になれば再計画する。

評価候補は穴の数、総高さ、最大高さ、凹凸、消去行数、送信攻撃量、
受信攻撃量、危険度。重みはJSONで調整する。
次に公開情報と残りbagの制約に基づくモンテカルロ探索を追加し、
機械学習AIも同じ観測・コマンド境界へ接続する。

## 評価
固定した複数seedで、勝率、送信攻撃量、受信攻撃量、消去行数、
生存tick、1判断あたりの計算時間を記録する。
攻撃力は固定tickに対する送信行数などで比較し、定義と設定を結果に添える。
ルール設定、AI重み、seed、コマンド履歴を保存して再現できるようにする。
