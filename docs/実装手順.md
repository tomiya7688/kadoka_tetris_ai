# 実装手順

既存の開発予定.mdを具体化した順序。優先度の指定があればそちらを優先する。
この文書は工程案であり、以下の機能はすべて未実装。

配布は最終工程ではない。**開発開始直後から、常に配布ビルドを作れる状態を維持しながら進める。**
`build.bat` などの単一入口、または同等のビルダー1コマンドから配布物を生成し、変更後は通常テストに加えて配布物の簡易スモークテストを行う。

ここで必須なのはZIPファイルそのものを自動生成することではない。**ビルド結果が配布用ディレクトリとして自己完結しており、そのディレクトリ一式をZIP化すればそのまま配布できること**を要件とする。

| 順番 | 作業 | 完了条件 |
| --- | --- | --- |
| 0 | 配布ビルド基盤 | 1コマンドで自己完結した配布用ディレクトリを生成でき、必要ならその一式をZIP化して第三者へ渡せる。簡易スモークテストの入口がある |
| 1 | 盤面、ミノ定義、7-bag | 7個単位の一意性、seed再現性、衝突をGUIなしで検証し、配布ビルドを壊さない |
| 2 | コマンド、回転、落下、固定、消去、HOLD | 回転表・敗北条件を仕様化し、操作列の再現テストが通る |
| 3 | 固定tick進行と外部コマンド入出力 | 不正入力の拒否と、両陣営への独立した操作を検証 |
| 4 | 最小GUIと人間操作 | 状態表示と手動操作を確認し、コアのGUI非依存を維持 |
| 5 | 到達可能手の探索と評価関数AI | 合法な操作だけで単独プレイでき、固定seedで評価可能 |
| 6 | 対戦、おじゃま、攻撃分析 | 相殺・同時攻撃・敗北のテスト、人間対CPU・AI対AIの確認 |
| 7 | モンテカルロ探索 | ツモ制約を守り、基準AIと同一条件で比較 |
| 8 | 機械学習AI | 観測・行動契約と学習/評価データの分離を検証 |

各工程の完了前に、原則として以下を行う。

1. 通常の自動テストを実行する。
2. 単一のビルド入口から配布ビルドを生成する。
3. 配布用ディレクトリに対して、起動確認・必須ファイル存在確認・設定/UserData初期化など、その時点で可能な簡易スモークテストを行う。
4. 実行した検証と未検証事項を記録する。

新しい依存関係、設定、アセット、パス処理を導入した場合は、開発環境だけでなく配布ビルドでも成立することを確認する。
Python/Pygameを継続するかどうかも、この常時配布要件を満たせるかを基準に早期判断する。

初回実装前に、GitリポジトリとGitHub公開先を設定・確認する。
詳細設計は対象工程に着手したときに docs/機能名/機能説明書.md へ追加する。
