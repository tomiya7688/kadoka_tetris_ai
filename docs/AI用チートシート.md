# 開発AI用チートシート

この文書はコーディングを担当するAI向け。ゲームを操作するAIの仕様は設計書を参照。

## 作業開始
1. AGENTS.md、開発予定.md、評価者からのフィードバック.mdを読む。
2. Git管理されていれば git status --short --branch と git remote -v を確認する。
3. 対象の設計と既存コードを読み、小さな完了条件を決めて作業する。

## 判断の早見表
| 変更内容 | 配置 |
| --- | --- |
| ミノ・衝突・ライン消去・ツモ | src/tetris/core/ |
| tick進行・対戦・コマンド受付 | src/tetris/application/ |
| 候補探索・評価関数・戦略 | src/tetris/ai/ |
| 描画・キー入力・外部通信 | src/tetris/adapters/ |
| ルールや評価重み | config/ |
| 詳細仕様 | docs/機能名/機能説明書.md |

## 守る契約
- 盤面を書き換えるのはコアだけ。
- 人間もAIも外部プログラムも同じコマンド契約を使用する。
- 未来のツモ・内部乱数状態をAIへ漏らさない。
- 同一設定・seed・コマンド列なら同一結果にする。
- 推測した仕様は実装前に文書化し、公式ルール準拠と断言しない。

## 検証コマンド（コード追加後、プロジェクト直下）
~~~powershell
python -m unittest discover -s tests -v
python -m compileall -q src tests
git diff --check
~~~
テスト0件は機能検証の成功に数えない。gitコマンドはGit管理開始後に使用する。
ゲームの起動方法は実装時にREADMEへ追記する。

## 作業終了
検証結果と差分を確認する。完了項目を開発予定から削除し、
対応済みフィードバックを履歴へ移す。未完成の機能は完了扱いにしない。
変更概要・検証結果・残作業を短く報告する。
